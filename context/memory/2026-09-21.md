# 2026-09-21

## Goal
User reported `SQL:HABIT_CHECKINS_ROUTES:ERROR` on every Friends with Habits check-in.
Find root cause; stop the mobile app showing raw backend errors; user suspected a
backend/mobile contract break needing a version bump + EAS build.

## Root cause (proven, not inferred)
**The three 2026-09-19/20 habits migrations never ran on `main`.** `deploy.sh` calls
`deploy_waves` *before* `run-migrations.sh` (deliberate: "never migrate the schema
underneath a rollout that is already wedged"). The 2026-09-20 stage→main deploy hit the
messages/websocket/maps ImagePullBackOff that `f4ff81bc1` fixes; `set -e` ended the job
there. users-service had already rolled onto the savings build (ac56442da), so it served
new code against the pre-migration schema. `POST /habits/checkins` 500s with
`column "savedAmount" of relation "habit_checkins" does not exist`. The habit list and
the daily digest are down for the same reason (`getDetailByUser` / `getActiveForReminders`
SELECT the new columns unconditionally). 0cbbca947 had already filed this as a WIP
follow-up ("confirm the three migrations ran") — it was the incident.

**NOT a mobile/backend contract break.** The published app (1.8.0/45) sends nothing the
new backend rejects; a new build would not have fixed it. Told the user; did not merge to
niche/HABITS-main.

## How it was proven
No docker daemon in the sandbox. Started system PG 16 + apt-installed postgis, ran the
users-service migrations against it, drove the *real* `createCheckin` handler through 13
scenarios. All 201 on the current schema; all 500 with the three migrations rolled back,
with the exact production error. Reproduced at the SQL level too.

## Why it was fatal rather than harmless
Knex emits `DEFAULT` for an `undefined` value in an INSERT rather than dropping the key.
`createCheckin` declares `let savedAmount` and always spreads the key, so *every* check-in
named `"savedAmount"` in the column list — including from app builds that never heard of
savings. That makes every optional column a hard schema dependency, defeating the
expand/contract contract the deploy pipeline is built on. The existing unit test that
looked like it covered this passed an object with **no key at all**, which is not what the
handler builds — that is exactly how it hid.
