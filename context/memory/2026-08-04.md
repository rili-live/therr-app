## Session 4 — algorithmKey ownership fix (commit b57a7b576, pushed to origin/general)
- Closed the invariant hole surfaced in session 3. The distributor resolved its profile from `contextUserIds`, but reactions are stamped with `x-userid` (reactions-service reads the header, ignores the body for identity). A batched caller could therefore stamp one user's rows with another's `algorithmKey`. Profile now comes from the header user, falling back to a single-user context list so header-less internal triggers still resolve the intended profile; only an unattributable batch takes the default.
- Replaced the multi-user test with 4 ownership tests (owner deliberately not first in the list, so none can pass on list order). users-service 537 passing, tsc 0, lint 0 errors.
## Session 5 — login-path distributor fix (commit c100afe5b, pushed to origin/general)
- The login-path distributor call had never worked: gateway `POST /auth` uses `authenticateOptional`, so a fresh login has no token; `handleServiceRequest` forwards `'x-userid': ''`, `internalRestRequest` passes it verbatim, and reactions-service 401s on `!userId`. `createReactions` catches and logs, so login silently never seeded a stream — only the notifications-poll path did.
- Key trap: setting `x-userid` at the old call site would have been *worse* than the bug. That site sits on the bare username/email/phone lookup, **ahead of `validateCredentials`** — it fired on failed attempts, so populating the header would have let any unauthenticated caller trigger stream activation for any account by submitting its email.
- Moved the trigger into `issueUserSession` (reached only when `isValid`; shared by password/SSO and passwordless-phone; **not** on the `refreshToken` path, so no per-refresh amplification) and set `x-userid` to the authenticated user explicitly.
- New `tests/unit/handlers-auth-thoughtDistributor.test.ts` (5 tests). Verified against pre-fix code: wrong-credentials seeded anyway, and `x-userid` arrived as `''`.
- users-service 542 passing, tsc 0, lint 0 errors.
