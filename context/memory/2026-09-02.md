# 2026-09-02

## Goal
Blink the chameleon's eyes on the Friends with Habits splash screen, the way the Therr
logo spins just before the splash hides. PR targets `niche/HABITS-general`.

## Deliverables
- `TherrMobile/main/components/SplashLogoSpinner.tsx` — HABITS now blinks twice (~680ms,
  the beat the other brands spend spinning) before the fade-out; other brands still spin.
  Lids are views swept over each eye by a reanimated transform (scaleY + translateY, so
  the blink stays off the layout path), positioned from fractions of the logo box.
- New guard `__tests__/components/splashLogoEyes.test.ts` — dependency-free PNG decode
  (zlib + scanline unfilter) re-measures `bootsplash_logo@4x.png` and fails if a
  regenerated logo moves or resizes the eyes out from under the lids.

## Decisions
- Kept the baked PNG instead of re-rendering the chameleon as SVG, so the JS overlay still
  matches the native bootsplash pixel for pixel.
- Eye geometry measured off the artwork, not off `habits-logo.svg` — the bootsplash logo
  composites the chameleon above the wordmark, so the SVG's coordinates don't carry over.
- Lid color is sampled from the eye socket, which makes the lid's overhang past the round
  sclera invisible — no clipping or `overflow: hidden` needed.
- 1dp lash line on the lid edge: a closed eye read as a *missing* eye without it, and
  `hairlineWidth` was too faint at a 12dp eye.

## Open threads
- Not verified on a device/emulator — the blink was checked by compositing lid frames onto
  the real artwork, and by lint + the new geometry test.
- A fresh clone needs `therr-js-utilities` and `therr-react` built before
  `pr:tsc-baseline:mobile` or most of the mobile jest suites will fail with TS2307 /
  "Could not locate module therr-react/services".

# Habits: local-time streak reminders + evening "last chance" nudge

## Goal
Enhance Friends with Habits notifications without becoming spammy: keep the morning streak
status push, add a "last chance" reminder mid-to-late in the user's own local day.

## Deliverables
- PR rili-live/therr-app#2845 → `general` (shared: backend, mobile timezone report, docs).
- PR rili-live/therr-app#2846 → `niche/HABITS-general` (merge of #2845 + PACT_ENDED manifest fix).
- PR rili-live/therr-messaging-automator#12 → `main` (counter shape + scheduling notes).
- New: `users-service/src/utilities/localReminderSchedule.ts` (pure, 18 tests) and
  `checkinNudgeFreshness.ts` (send-time relevance gate in the queue worker, 9 tests).
- `handlers-habits-digest-last-chance.test.ts` (11 tests, clock pinned via sinon fake Date).

## Decisions
- Reused `eveningCheckIn` rather than adding a `streakLastChance` type: a new type is inert
  until a fresh Android build ships from the niche branch; this one is already wired
  (enum, intent action, manifest, REMINDER_ACTION_KEYS, Layout tap routing, 3 locales).
- Fallback timezone is `America/Chicago`, not UTC — it is the zone the one Cloud Scheduler
  job already fires in, so a user with no `settingsTimezone` keeps today's delivery time.
- The evening slot requires a **live streak**. Loss aversion is the only justification for a
  second push in a day; a user at zero still gets exactly one.
- Freshness gate **fails open** — a read failure sends. Silence on this feature is invisible;
  an extra push is not.
- Gate runs *before* the 5/user/day cap in `sendOne`, so a stale row cannot spend a send.
- `settingsTimezone` is validated in the handler (400 on junk), not coerced in the store.
- Existing digest suites set `HABIT_LAST_CHANCE_REMINDERS_ENABLED=false` per test (in their
  stub fns, NOT a mocha root hook — root hooks are global across files and fought the
  last-chance suite depending on file order).

## Open threads
- Nothing niche-only in the feature itself; #2846 exists to carry the merge down to the
  branch that builds the Android app, plus the pre-existing PACT_ENDED gap.
- `push-notifications-service` integration tests need Redis (no Docker here) — 2 failures
  there are `Connection is closed` in an `after all` hook, unrelated. `pre-push` bypassed.
- Post-deploy: watch `usersWithoutTimezone` fall, `lastChanceSent` vs `streakAtRiskSent`,
  and `already-checked-in` in `notificationQueue."lastError"` (the gate working — not in
  the digest response). Push-preference UI is still missing; two columns are now read and
  no client writes either.
