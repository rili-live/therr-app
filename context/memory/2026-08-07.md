# 2026-08-07

## Goal
Add an argument to the prod-debug script so the GCP Cloud Run functions can be debugged
alongside the GKE cluster. Script is `_bin/prod-debug/collect-incident.sh` (the user calls
it "prod_debug.sh"); there is no file by that literal name.

## Deliverables
- `--cloud-run` flag (aliases `--cloud-functions`, `--gcf`; `--cloud-run=<names>` narrows).
  Additive — cluster sections still run, so a function failure correlates with in-cluster
  activity at the same moment.
- Because the automators are Cloud Scheduler-driven, an empty 30m window falls back to the
  most recent invocation within `THERR_CLOUD_RUN_LOOKBACK` (default 30d) and prints its age.
- Per function: Cloud Scheduler job state, last invocation start-to-finish (isolated by
  `labels.execution_id`, chronological), deduped errors. All through `redact()`.
- Docs updated (`docs/PROD_DEBUG_CLAUDE.md`). Branch `claude/prod-debug-cloud-run-arg-o9un1s`,
  commit a0c49f5, pushed. No PR opened (not requested).

## Decisions
- Log filter matches BOTH `cloud_function` (Gen-1, what we run today) and
  `cloud_run_revision`, so a Gen-2 migration doesn't silently empty the section.
- Skipped a `--cloud-run-only` flag — the ask was explicitly "as well as the GKE cluster".
- `epoch_of()` handles GNU and BSD `date`; `reverse_lines()` is awk because `tac` is GNU-only
  and `tail -r` is BSD-only.

## Open threads
- Branch is based on `main`. `_bin/**` is shared code, so any PR from it must target
  `general` — a niche branch would make it dead code.
- Verified only against a stub `gcloud` (no gcloud/kubectl in the container). Exercised:
  window-empty fallback, in-window hit, zero-entries-in-30d, no-jq path, gcloud-absent,
  `--cloud-run=<name>` parsing, unknown-flag exit 2. Still needs one real run against prod.
