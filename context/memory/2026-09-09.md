# 2026-09-09

## Goal
Give users a "continue solo?" / "archive?" choice for habits whose pact invite is
still unanswered, so streak push notifications stop being annoying for habits
nobody has joined. Split PR (backend/shared on general; mobile on niche).

## Deliverables (branch claude/habit-solo-archive-notifications-ckp080)
- Backend (general): UserHabitsStore.getDetailByUser exposes `pendingPactId`;
  new `reviveArchivedByHabit`; acceptPact revives creator's/accepter's archived
  habit on acceptance; new `continueSoloHabit` handler + route + gateway route.
  Continue-solo abandons pending pacts (not delete — keeps invite count) and is
  gated by solo-unlock (+ cap when un-archiving). Unit tests added.
- Shared (therr-react): UserHabitsService.continueSolo, action + type + reducer,
  IUserHabit.pendingPactId.
- Mobile (niche): Dashboard loads userHabits, filters archived, awaiting-partner
  HabitCard gets continue-solo/archive buttons + confirm modal + spinner state;
  pactState helper + tests; locales en-us/es/fr-ca.

## Decisions
- Continue-solo ABANDONS the pending pact (terminal "going alone"); archive keeps
  it pending and auto-revives on acceptance. Clean split, no new column needed.
- Applied the solo-unlock gate to continue-solo per "account for the constraints
  of creating solo habits" — documented so a reviewer can relax it.
- Archiving reuses existing user_habits archived state (reminder pass already
  filters status='active'); no new push type/producer.
