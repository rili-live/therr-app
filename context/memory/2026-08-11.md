# 2026-08-11

## Goal
`/work-plan` on `claude/work-plan-7ziucc` (feature branch off `general`). Deploy state was
idle — general == main, nothing queued — so the plan took a fresh Tier 1 backend batch:
**1.3 User deletion completeness (GDPR / app-store)**.

## Decisions (answered via AskUserQuestion)
- DMs hard-deleted both directions; forums **reassigned** to `SUPER_ADMIN_ID`, not deleted
  (a forum is shared space — deleting one destroys other members' messages). Mirrors what
  maps-service already does with spaces.
- Batch extent: DB-side + websocket redis session. S3 media deliberately excluded.

## Deliverables (commit b95fa37 → pushed)
- messages-service: new `DELETE /delete-user-data` + `deleteByUserId` on DirectMessages and
  ForumMessages, `reassignByAuthorId` on Forums, local `constants/index.ts` (3rd copy of
  SUPER_ADMIN_ID — logged in Tier 5.4 as a hoist candidate rather than deviating mid-batch).
- websocket-service: `DELETE /delete-user-data` tears down the redis session;
  `redisHelper.removeUser` now **returns** its pipeline instead of fire-and-forget.
- users-service: deletes `main.notifications` + `main.notificationQueue`; fan-out extended
  to messages + websocket and moved `Promise.all`+`console.log` → `allSettled` + per-service
  error span carrying the deleted user id.
- `global-config.js`: `baseWebsocketServiceRoute` off the existing cluster-ip (7743).
- All deletes intentionally **unscoped by brand** — identity row is gone, so no brand should
  retain the rows. This is the part a future regression would get wrong invisibly.

## Verified
users 650, messages 154, websocket 155 (with real Redis) — all passing. eslint 0 errors on
every changed file; tsc clean for all three services. Gateway confirmed not to proxy
`/delete-user-data`, so the new endpoints stay internal.

  (global-config.js is a root file, so everything counts as changed) and two
  `therr-api-gateway` integration tests cannot pass when Redis is present: they set a 2s
  Redis TTL then wait for expiry inside mocha's 2s default timeout. They `skipTests`-return
  when Redis is absent, which is why CI never sees them. Needs `this.timeout(5000)` — a
  separate commit, not this batch.
- Ops follow-ups surfaced and still unchecked: verify the notificationQueue migration
