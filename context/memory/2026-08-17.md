# 2026-08-17

## Goal
Friends with Habits had no way to create a habit for personal tracking without
inviting a friend. Ended up reshaping the invite requirement rather than
removing it.

## What was actually there
Solo habits were built end-to-end (POST /habits/user-habits, startUserHabit,
handleStartSolo, splitHabitsByPactState treating pactless goals as live) but
unreachable: solo creation was gated on having already sent a pact invite, the
wizard was the only creation flow, and its step 2 refused to advance without a
partner. A closed circle with no exit.

## Deliverables
Shipped in two passes. First removed the gate entirely; the user then asked to
keep it at a **three-invite threshold** instead, which is what landed.

`general`
- `HABITS_SOLO_UNLOCK_INVITE_COUNT` (default 3, env-overridable) in
  therr-js-utilities, next to HABITS_FREE_HABIT_LIMIT.
- `countInvitedByCreator` → `countDistinctInvitedByCreator`. Counting rows was
  indistinguishable from counting people at a threshold of 1; at 3 it would let
  one friend invited to three pacts clear the bar.
- `getSoloInviteProgress` returns {invitedCount, requiredCount, canCreateSolo},
  fails closed. Both the eligibility endpoint and the 403 carry the counts.
- Unlock is checked BEFORE the habit cap — a locked user at the cap must get
  403, not an offer to buy a slot for a feature they can earn free.

`niche/HABITS-general`
- Wizard step 2 skippable only when unlocked (`canAdvanceFromPartnerStep`);
  locked shows remaining-invite progress and a counted toast.
- Solo mode (`mode: 'solo'`) falls back to the partner step when locked — a
  shortcut through an open door, never around the lock.
- Progress surfaces on the onboarding overlay AND a dashboard banner. The
  overlay alone was not enough: it stops rendering after the first invite,
  which is exactly when 2 remain.
- `soloHabitUnlock.ts` (RN-free) is the single progress model both read.

## Decisions
- Threshold, not removal — the user's call. Framing: a target you can watch
  yourself approach is a reason to invite the next friend; an invisible
  one-invite toll was only a reason to leave.
- `hasProgress` is false when counts are absent (old server / unloaded), so the
  UI shows locked *without* "0 of 0" — worse than saying nothing.
- Guard still releases on habitGoals; "have you started" is deliberately looser
  than "have you unlocked solo".
