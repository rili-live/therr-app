# 2026-08-31

## Goal
Upgrade React Native with a risk-minimizing approach; pick the latest stable version
that won't jeopardize mobile development or deployment.

## Decision: RN 0.83.6 → 0.86.3 (not 0.87.1)
- 0.86 shipped with **no user-facing breaking changes** and specifically fixes Android 15+
  edge-to-edge when `edgeToEdgeEnabled` is false — exactly this app's gradle.properties config.
- 0.86.3 (2026-08-24) was patched *after* 0.87.0 shipped → still the actively maintained line.
- 0.87 rejected for now: AGP v9 adoption, strict-TS-API default, StatusBar props removed.
  Its one upside is that RN 0.87 removes the deprecated status-bar color APIs entirely,
  which would let us delete `patches/react-native+*.patch`.

## Deliverables
- RN 0.86.3, react/react-dom/react-test-renderer 19.2.3, @react-native/* 0.86.3, CLI 20.1.0.
- Required pair bump: reanimated 4.6.0 + worklets 0.12.1 (4.3/0.8 hard-cap at RN 0.85).
- screens 4.27.0; gesture-handler 2.32.0.
- Jest preset moved to its own package: `preset: '@react-native/jest-preset'`.

- Patches regenerated: react-native+0.86.3, react-native-screens+4.27.0,

## Gotchas found
- **gesture-handler 2.30.0 breaks on RN 0.86**: imports
  `react-native/Libraries/Renderer/shims/ReactNative`, removed with the legacy-arch renderer.
  Fixed in 2.32.0 without going to 3.x. A deep-import sweep over node_modules is the cheap
  way to find this whole failure class.
- RN patch shrank: `@react-native/jest-preset` now ships its own RefreshControlMock, so that
  half of the old patch is obsolete. StatusBarModule half is still required at 0.86.3.
- worklets moved `android/build.gradle` → `build.gradle.kts`; upstream still only wires
  `prepareWorkletsHeadersForPrefabs` into `preBuild`, so the Gradle-sync prefab race persists.
- `expo-modules-core` entry in metro.config.js `extraNodeModules` is dead (expo is not a
  declared dep anywhere) — pre-existing, not caused by this upgrade.

## Late finding: the react-native patch is inert on Android
`patches/react-native+*.patch` edits `ReactAndroid/src/.../StatusBarModule.kt`, but the build
resolves `com.facebook.react:react-android:0.86.3` as a **prebuilt AAR from Maven** (no
`react.buildFromSource`, zero `:ReactAndroid` tasks in the build log). Verified by
disassembling the signed release APK: `StatusBarModule$b` still contains 16 `ValueAnimator`
refs and 2 `setStatusBarColor` refs — exactly the code the patch deletes.
Pre-existing, not caused by this upgrade (the Gradle cache holds a 0.83.6 AAR too).
TherrMobile/CLAUDE.md § "Deprecated Android 15 APIs" asserts this patch works; it does not.
Deprecated-API refs in the release APK also come from androidx.activity, material,
`com.swmansion.rnscreens.ScreenViewManager`, and RN's own `views/view` — so the patch was
never going to clear the Play Console report on its own.

## Post-upgrade bug: Paper dialogs mispositioned (fixed)
RN 0.86 **removed `StyleSheet.absoluteFillObject`**. Spreading it yields `{}` (legal JS,
silent), so react-native-paper's `Modal` wrapper lost `position: 'absolute'` and laid out
in normal flow: the `flex: 1` backdrop shrank to the leftover space (scrim covered only
the top ~57% of the screen) and every `<Dialog>` dropped to the bottom. Where the dialog
style also had `maxHeight: '<pct>%'` (styles/modal/*.ts), the percentage then resolved
against the collapsed wrapper and clipped the surface, so `Dialog.Actions` rendered
*outside* the card. Diagnosed from `adb shell uiautomator dump`: backdrop `[0,0][1080,1373]`,
wrapper `[0,1505][1080,2337]` — i.e. stacked, not overlaid.
Fix: second hunk in `patches/react-native+0.86.3.patch` restoring
`absoluteFillObject: absoluteFill`. Verified on emulator — backdrop now `[0,0][1080,2400]`,
wrapper `[0,132][1080,2337]`, dialog centered. Other affected consumers: paper Menu/
FABGroup/BottomNavigationBar/TouchableRipple/ActivityIndicator, bootsplash,
country-picker-modal.
