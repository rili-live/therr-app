## Decisions
- Freeze notice is **both** in-app toast and push, not one: the toast reaches the
  user who just tapped, the push reaches a backgrounded device.
- Absent `graceDaysConsumed` / `freezesRemaining` reads as "no freeze", never as
  one. During rollout the field rides on queue rows written by the old
  users-service; claiming a save that did not happen is the worse failure.
- `streakFreezes.ts` duplicates backend constants (1 / +1 per 7d / cap 3) because
  the rule must be stated before any `habits.streaks` row exists. It fails by
  lying, not by breaking — change both together.
- `docs/WORK_IN_PROGRESS.md` edits made on `general` only, then merged down, to
  keep the file single-writer per the standing reconcile item.
