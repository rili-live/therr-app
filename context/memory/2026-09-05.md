# 2026-09-05

## Session — Android notification small icon shows Therr logo (niche/HABITS-general)

### Goal
Friends with Habits pushes render the Therr "T" in the Android status bar (reported on
the habits daily-reminder push, "one check-in gets your streak going"). Should be the
chameleon glyph. Branch `claude/android-notification-icon-qhh28p`, based on
`origin/niche/HABITS-general`.

### Root cause
`ic_notification_icon` is byte-identical between `general` and `niche/HABITS-general` —
it had simply never been re-branded. Nothing in a niche build overrides drawables (no
product flavors; brand selection is `brandConfig.ts` + per-branch assets), so both push
paths land on the Therr mark: `AndroidManifest.xml`'s
`com.google.firebase.messaging.default_notification_icon` for notification-payload
messages, and notifee's `smallIcon` default in `main/utilities/pushNotifications.ts` for
data-only ones. push-notifications-service also sets `icon: 'ic_notification_icon'`
explicitly in `firebaseAdmin.ts`, same resource name resolved per-app — so nothing
backend needed to change. It is *not* every notification type; it is all of them.
Invisible because only the collapsed 24dp glyph is wrong — the expanded shade shows the
correct app icon and name.

### Deliverables
- `drawable-anydpi-v24/ic_notification_icon.xml` + the five density PNGs, regenerated as
  the chameleon silhouette.
- `TherrMobile/resources/icons/build-notification-icon.py` — derives the silhouette from
  `main/assets/habits-logo.svg` (shapely booleans, cairosvg raster).
- `TherrMobile/__tests__/assets/notificationIcon.test.ts` — 9 assertions; verified it
  fails (3 cases) against the Therr mark it replaced.

### Decisions
- The launcher icon can't be reused. Android reads the small icon's **alpha only** and
  repaints every opaque pixel, and the logo's eyes/stripe/smile are color contrast on an
  opaque body, so flattened it is a blob. Silhouette rule: body+ink opaque, white sclera
  punched out, pupils added back — `(head ∪ rims) − scleras ∪ pupils`.
- Dropped the forehead stripe. Nostrils and smile are dark-on-dark and vanish for free;
  the stripe is light-on-dark so keeping it means cutting it, and at 24dp the cut lands
  on the head's peak and reads as damage. Compared both at 24/36/48/72/96px.
- 22.5dp of artwork in the 24dp canvas — the footprint the Therr mark already used, so
  the two brands' status-bar icons read at one size.
- Generated, not hand-drawn: the path data is otherwise an unrecoverable blob. Same
  posture as `resources/fonts/fix-icon-font-bearings.py`.
- Kept the PNGs in sync even though they never ship (`minSdkVersion` 25, `anydpi`
  outranks every density qualifier) — a stale Therr mark sitting in `drawable-xxhdpi/`
  is a landmine.
- `values/colors.xml` `therr_blue` is already the habits purple `#3B2A4E` on this branch,
  so the notification accent color needed nothing. Name is a legacy misnomer; left alone.

### Open threads
- Not verified on a device. Geometry was checked by rasterizing the committed vector and
  diffing it against the committed PNGs (identical at 24 and 96px), and by eye on light
  and dark grounds at all five densities.
- Jest/ESLint could not be run in this container — no `node_modules` anywhere, and a full
  mobile install pulls the licensed `react-native-background-geolocation`. The new suite
  was run green under a standalone jest + ts-jest against the real files; it imports only
  `fs`/`path`, so nothing RN-specific is untested.
- iOS is unaffected (uses the app icon), and `general` deliberately keeps the Therr mark.
