## Goal
Debug `_bin/push-debug.sh` failing at link 3 with `jq: error ... Cannot iterate over null`.

## Findings
- Gateway/service wiring for the diagnostics endpoints is correct end-to-end
  (`/v1/push-notifications-service/notifications/diagnostics` → router → handler,
  which always returns `byBrand`).
- The jq error was a masked HTTP error body. `curl -sS` doesn't fail on non-2xx, and
  every error in this stack returns `{ statusCode, message }` (therr-js-utilities
  `configure-handle-http-error`), which has no `.byBrand`. `set -euo pipefail` then
  killed the script at link 3, so links 2/4/5 never ran.
- Most likely real cause on prod: 403 "Invalid Access Levels" (token not SUPER_ADMIN)
  or 401 (expired JWT).

## Deliverables (uncommitted, on `general`)
- `_bin/push-debug.sh`: added `request()` helper capturing body + HTTP status;
  `fail_response()` prints the raw body plus per-status hints (401/403/404/429/5xx);
  shape guards before each jq filter; link 4 still tolerates 502 since that carries
  the FCM rejection in `.result`; unknown `--brand` now prints "NOT FOUND" instead of
  silently dropping the `thisBrand` key.
- Verified against a local mock server: 403, 404, happy path, FCM-rejection,

## Notes
- Bash helper must uppercase the HTTP verb — Express matches verbs case-sensitively,
  so `curl -X get` would 404/501.
- Redirection order matters: `jq . >&2 2>/dev/null`, not `2>/dev/null >&2` (the latter
  points stdout at /dev/null and swallows the body).

  the brand-correct `habits/login.hbs` (sends `x-brand-variation: habits`) is only at
  /login. Whatever form they used was the therr-client-web SPA, which hardcodes
  `BrandVariations.THERR` (interceptors.ts:43, server-client.tsx:41).
- Then a 404: **the entire push-diagnostics feature is unmerged.** Present on
  origin/general, MISSING on origin/stage and origin/main. Not deployed to prod.
- Critically, `13e0e4058 fix(push): address iOS pushes to a bundle id that actually
  ships` is also unshipped — the real iOS Habits push bug is already fixed on general
  and just sitting undeployed. ~12 commits in origin/stage..origin/general.

## Gateway auth bug FOUND + FIXED (after deploy landed)
- After deploy, link 3 passed but link 2 returned 403 "Invalid Access Levels" for a
  real SUPER_ADMIN. Cause: the public-profile entry in `authenticate.unless` was an
  **unanchored** regex, so `/users/<uuid>/push-diagnostics` matched it and skipped
  `authenticate` entirely → `authorize` read an empty access-level list → 403 for
  everyone. Skipping auth does NOT make a route public; it makes it un-authorizable.
- Blast radius was limited: that was the only GET route under `/users/:id/...`.
  The POST send-test was unaffected (`methods: ['GET']`), so link 4 always worked.
- Fix: anchored with `\/?$`; extracted the whole skip-list to
  `therr-api-gateway/src/config/unauthenticatedPaths.ts` (index.ts starts a listener
  so the list was untestable inline — same precedent as habitsSubdomainRoutes.ts).
  Verified extraction behavior-identical over 220 path/method combos except the two
  intended changes. Added 19 unit tests incl. a "list hygiene" test that fails on any
  future unanchored `/users/:id` pattern. Lint + tsc clean, 281 gateway tests pass.
- **Needs another deploy** (general → stage → main) before link 2 works in prod.

## Second task: Android release build broke after `npm run android:clean`
- CMake error: worklets' `android/build/generated/source/codegen/jni/` "not an existing
  directory" + `react_codegen_rnasyncstorage` "not built by this project".
- Cause: `./gradlew clean` wipes every autolinked lib's `node_modules/<lib>/android/build`,
  including codegen output. `:app:configureCMake*` consumes those dirs via
  `Android-autolinking.cmake` `add_subdirectory`, but Gradle has no task edge to the
  libraries' `generateCodegenArtifactsFromSchema` (only prefab-publishing libs get
  incidental ordering; async-storage doesn't publish prefab). Not the prefab-headers
  patch issue — different error.
- Fix: `./gradlew generateCodegenArtifactsFromSchema` (root, runs for all 25+ lib modules,
  ~30s) after any clean. Appended it to the `android:clean` npm script so clean is
  self-consistent. Verified `:app:configureCMakeRelease[arm64-v8a]` now succeeds.
