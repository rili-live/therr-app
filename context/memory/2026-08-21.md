## Location-based bot posts (therr-app + therr-ai-automator)

Goal: bot posts read as stilted because nothing about them is anchored anywhere.
Give some bots a home city, have them write about it, and put those posts in a
new user's feed once they share their location.

Both repos on `claude/location-based-bot-posts-4xx8hb` (therr-app's branch is
`general` + VERSIONS.txt, so the backend/shared work is landable).

therr-app:
- `20260821000001_main.thoughts.location.js` — latitude/longitude/locality,
  nullable, partial btree index on (latitude, longitude) WHERE NOT NULL.
- `ThoughtsStore.getRecentThoughts` takes an optional `nearLocation`: bounding
  box (indexable) + ST_DWithin (exact), distance aliased into the score so a
  geo-weighted profile can rank by it. PostGIS is already enabled in the users
  DB (20230815184654_main.users.js).
- content-ranking profiles gained `localMatchBoost` + `localFeedRadiusMeters`
  (env-tunable). PULSE 1.4 / 60km — the boost is applied at activation, never in
  SQL, so PULSE's emitted expression stays byte-identical.
- Distributor runs a third candidate query for the reaction owner's home point;
  `UserLocationsStore.getPrimary` accepts a first ping (getDwellings needs 3
  distinct days, which a new account can never have) with a 30-day recency guard.
- `createUserLocations` re-seeds the stream, gated on the shared distributor
  window (rows are keyed on ~111m-rounded coords, so pings are continuous).
- Seed `006_local_bot_users.js`: 12 metro bots + declared-home userLocations.

therr-ai-automator: `config/locales.ts` (12 metros, colour incl. everyday
gripes), joined to bot homes **by proximity, not by key**; LOCAL_THOUGHT_CHANCE
0.4; only local posts get coordinates, written as a complete pair or not at all.

Bug caught by a test I wrote for it: `Number(null)` is 0, so a userLocations row
with null coordinates resolved to Null Island and ran a local query against it.
