## Android keyboard overlap on the thought reply composer

Bug (screenshots): on ViewThought the sticky reply input is covered by the
Android keyboard — the user cannot see what they type. Root cause is edge-to-edge
(API 36): the window no longer resizes for the keyboard, so `adjustResize` does
nothing for a bar anchored below the KeyboardAwareScrollView.

Fix on `claude/android-keyboard-input-overlap-q7aety` (off main, commit 2fdc44f):
wrapped composer + footer in `KeyboardStickyView`, hid the footer while the
keyboard is visible (`useKeyboardState((s) => s.isVisible)`), made the input
`multiline` with a ~5-line cap. The cap goes on `contentStyle`, not `style` —
Paper only pins an explicit height on a multiline input when one arrives through
`style`, so a `maxHeight` there clips text instead of letting the input scroll.
Dropped `onSubmitEditing` (never fires with multiline); the send icon is the only
submit path. Jest mock gained `KeyboardStickyView` + selector-aware
`useKeyboardState`.

Green: eslint, mobile tsc baseline 101=101, Jest 1277 / 53 suites.

## Sweep for the same bug class (commit 6a70827)

User asked to fix every other instance. Five more, all the same edge-to-edge
root cause, all fixed:
- DirectMessage + Groups/ViewGroup composers: `behavior={ios ? 'padding' :
  undefined}` — undefined behavior hits `default: return {}` in the library, a
  literal no-op. Now `behavior="padding"` + `automaticOffset` (measures true
  screen position via native `viewPositionInWindow`; replaces the magic iOS
  `keyboardVerticalOffset={90}`).
- Invite/CreateConnection: KAV over a one-item FlatList, Android `height`
  measured a parent-relative frame. Now KeyboardAwareScrollView.
- ForgotPassword + EmailVerification: plain ScrollView, and `bodyScrollSmall`
  centers the form (justifyContent center, minHeight 70%) so the email field is
  mid-screen. Now KeyboardAwareScrollView.
- ViewEvent RSVP dialog: Paper has zero keyboard handling. Paper centers the
  dialog and centering counts the child's margins, so marginBottom =
  keyboardHeight lifts it by half that — clears whenever dialog height ≤ space
  above the keyboard.

Green again: eslint 0 errors, tsc 101=101, Jest 1277 / 53.
